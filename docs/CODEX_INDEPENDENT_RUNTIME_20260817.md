# AutoFish 脱离 Codex 自主运行交付记录

日期：2026-08-17

## 结论

AutoFish 0.7.0 的正常上架链路已不再需要 Codex 参与选品、写文案、生成精品图、视觉质检、建档、排队、填写网页、上传图片、点击发布或回写结果。Codex 只用于本次研发与验收，不是生产运行依赖。

运行时仍需要一台保持闲鱼卖家工作台登录的本机 Chrome。登录失效、验证码、滑块、账号风控、页面新增必填项以及提交结果不明确会进入人工任务；系统不会绕过这些平台控制。

## 自主闭环

1. Celery Beat 根据 GLOBAL/PUBLISH 策略扫描 `REVIEW_READY` 草稿。
2. Worker 再次校验真实供应链来源、禁止词、价格底线、草稿哈希和精品图视觉 QA。
3. Worker 创建固定类型 `PUBLISH_PRODUCT` 浏览器任务，不向扩展下发任意脚本、选择器或路径。
4. Chrome 扩展使用独立桥接令牌领取任务，登录 Cookie 始终留在 Chrome。
5. 扩展通过租约专属图片接口逐张下载精品图，并同时核验数据库清单、响应头和本地 SHA-256。
6. 页面执行器上传 1–9 张图片，填写描述和售价，等待闲鱼智能识别属性并回读字段。
7. 只有发布按钮可用、字段一致、无登录/风控信号时才进入 `SUBMITTING`。
8. 点击后以商品 ID 链接或可见的“发布成功/上架成功”为成功证据；成功后草稿与自主任务同步转为 `PUBLISHED`。
9. `SUBMITTING` 后若断线、超时或结果不明确，固定转 `MANUAL_REQUIRED`，绝不自动再次点击。

## 三重放行条件

- NAS：`AUTOFISH_XIANYU_BROWSER_PUBLISH_ENABLED=true`；
- 自动化控制：GLOBAL、PUBLISH 均启用且 PUBLISH 为 `AUTOMATIC`；
- 本机扩展源代码：版本 0.3.0，能力列表包含 `PUBLISH_PRODUCT`；Chrome 中已加载版本以系统“浏览器代理”状态为准。

缺少任一条件都不会形成无人值守最终提交。

## 运维要求

- Chrome 需要保持运行，扩展每 30 秒轮询一次；
- 闲鱼登录失效后只需在官方页面重新登录，不需要 Codex；
- 人工任务处理完后从 AutoFish 控制台重试，不要直接复制旧任务；
- 不要关闭提交后禁止重试保护；
- 闲鱼页面结构变化时先用单款预填验表，再恢复自动发布；
- 发货、退款、支付、投诉和平台介入不属于无人值守发布执行器能力。
