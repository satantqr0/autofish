# AutoFish 演示数据防误发布加固总结

日期：2026-08-16（Asia/Shanghai）

## 结果

AutoFish 已建立统一的商品来源发布门禁。演示商品、无可追溯供应商 SKU 的商品和供应链路断裂的商品，无法进入闲鱼发布队列、生成可发布草稿、形成可执行发布动作、通过人工发布回填，也无法通过商家工作台浏览器桥接预填到发布页面。

真实商品 `AF-852354763336-MW` 继续通过门禁；生产库中的 10 个 `1688-DEMO` 商品全部被拦截。本轮没有创建第二个虚假真实商品，也没有发布任何演示数据。

## 防绕过层级

| 层级 | 防护时机 | 作用 |
| --- | --- | --- |
| 发布队列 | 创建 `PublicationTask` 前 | 阻止演示商品进入人工待审 |
| 草稿 | 创建 `XianyuDraft` 前 | 阻止产生新的演示发布载荷 |
| 动作预检 | 创建平台动作记录时 | 返回不可执行及具体拦截原因 |
| 动作执行 | 调用闲鱼 Adapter 前 | 阻止旧动作和预检后篡改 |
| 人工回填 | 关联真实闲鱼商品 ID 前 | 阻止把线上商品错误绑定到演示商品 |
| 浏览器预填创建 | 生成桥接任务前 | 阻止旧演示草稿进入工作台队列 |
| 浏览器预填领取 | Agent 取得载荷前 | 阻止排队期间发生的来源篡改 |

## 判定规则

- 商品说明明确包含“演示数据”或“仅用于演示”。
- 供应商代码为 `1688-DEMO`、`DEMO` 或 `DEMO-*`。
- 供应商名称包含“演示供应商”。
- 供应商来源类型为 `DEMO`。
- 供应商或供应商品链接使用保留的 `.example` 域名。
- 商品缺少已启用且可追溯的供应商 SKU，或供应商链路不完整。

判定集中在 `backend/app/services/publication_guard.py`，所有发布入口复用同一规则，避免规则漂移。

## 对抗验证

- 新演示商品不能生成闲鱼草稿。
- 历史遗留的 `REVIEW_READY` 演示草稿仍不能通过发布预检。
- 正常动作在预检通过后，如果商品被改成演示数据，执行阶段会改为 `BLOCKED`，Adapter 发布调用为 0。
- 演示商品不能通过人工发布回填绑定线上商品。
- 演示商品不能进入发布待审队列。
- 浏览器预填任务创建时拒绝演示来源。
- 正常预填任务排队后若来源被改成演示数据，代理领取阶段会把任务标记为 `BLOCKED`，不会收到发布载荷。

本地与 NAS 镜像内完整测试均为 103 passed，Ruff 全部通过。
