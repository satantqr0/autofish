## 草稿防重复发布修复

修复前，人工浏览器发布完成并回填真实闲鱼商品 ID 后，草稿 4 仍为 `REVIEW_READY`，存在被再次领取并重复发布的风险。

本轮为 `POST /api/v1/xianyu/manual-publications` 增加可选的精确 `draft_id`：

1. 校验草稿必须属于载荷中的商品。
2. 只有外部商品状态为 `ACTIVE` 时，才把目标草稿更新为 `PUBLISHED`。
3. 返回 `draft_id` 与 `draft_reconciled`，便于浏览器代理和审计判断是否发生状态迁移。
4. 完全相同的请求重放保持幂等，不重复创建商品，也不重复变更草稿。

涉及文件：

- `backend/app/schemas/xianyu.py`
- `backend/app/services/xianyu_manual.py`
- `backend/tests/test_xianyu_manual.py`

NAS 生产库复核：`xianyu_drafts.id=4` 的状态已经是 `PUBLISHED`，关联商品为 `13`。

## 尚未完成的真实交易边界

本轮已完整验证“真实货源读取 → 真实 SKU 建档 → 精品图片 → 真实发布 → 公开可见 → 状态回填 → 幂等防重复”的商品发布链路，但不能据此声称整套交易闭环已经完全无人值守：

1. 当前没有企业闲鱼开放平台发布权限，最终发布仍依赖已登录的卖家工作台浏览器会话。
2. 验证码、短信验证或平台安全校验必须交由账号持有人处理，系统不会绕过。
3. 尚无真实买家付款订单，因此采购下单、收货地址转交、供应商发货、物流单号回填、退款和售后闭环仍未完成真实资金订单验收。
4. AI 问价回复应继续保持低风险自动回复；涉及承诺、退款、纠纷或异常价格时进入人工复核。

下一阶段的正确验收目标是使用一笔可控的真实测试订单，验证订单接入至物流和售后的全链路，而不是继续堆叠未经订单验证的发布数量。
