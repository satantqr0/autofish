# 产品化运行手册

## 可交付状态

AutoFish `0.9.0` 已具备可持续运行的运营事实、决策与受控执行底座。商品、定价、评分、Canonical Feed、ClawHub 八大能力台、客服建议、平台动作状态机、定时任务、审计、备份和保护模式 UI 可独立运行；1688 合并 API Key 已通过只读搜索验证。闲鱼支持本人页面的规范化事实导入、官方/授权 Gateway 事件接入，以及发布、改价、下架、回复和物流回填的受控 Adapter 契约。

供应商发现、选品评估、商品诊断、闲鱼待审草稿、询价人工闭环、事实型客服建议和动作预检已经开放。代码已实现平台写入的确认/自动模式、幂等、限额、间隔、熔断和人工接管，但 NAS 生产环境仍保持写总开关与调度器关闭。自动采购/支付、退款/投诉、平台介入、验证码和风控步骤不进入无人值守路径。

## 三种运行模式

| 模式 | 配置 | 用途 |
|---|---|---|
| DEMO | `AUTOFISH_SEED_DEMO=true`、Adapter 总开关关闭 | 评审界面与业务规则 |
| LIVE_READY | `AUTOFISH_SEED_DEMO=false`、Adapter 总开关关闭 | 正式库、人工导入、等待授权 |
| READ_ONLY_LIVE | `AUTOFISH_SEED_DEMO=false`、Adapter 总开关开启、授权健康 | 真实只读同步 |
| CONTROLLED_WRITE_LIVE | 再启用写总开关，且单项策略通过门禁 | 获批 Adapter 的小流量受控写入 |

闲鱼人工网页快照不依赖 Adapter 授权：从本人已登录的个人页复制规范化商品事实后，在“闲鱼只读中心”导入。入口拒绝未知字段、Cookie、Token、非闲鱼域名、HTTP 链接、重复或不一致 ID、超过 24 小时的快照及数量冲突。完整快照中消失的旧在售商品会标记为 `REMOVED`，不会删除历史事实。

1688 搜索候选缺少结构化字段时，可在“1688 选品”使用“人工核验补全”。系统要求候选匹配的 1688 详情链接、24 小时内的来源时间、供应商标识、阿里 CDN 图片以及逐 SKU 的 ID、规格、成本、运费和库存；提交后生成幂等快照与审计记录。详见 [1688 候选人工核验补全](SUPPLIER_MANUAL_VERIFICATION.md)。

除 `CONTROLLED_WRITE_LIVE` 外都要求 `AUTOFISH_ADAPTER_WRITE_ENABLED=false`。进入受控写入前，还必须设置经授权的 `xianyu_adapter`、通过健康/权限检查、把目标策略先设为 `REVIEW`、降低每日限额并完成单条金丝雀验证。`AUTOFISH_AUTOMATION_SCHEDULER_ENABLED` 必须最后开启。

## 自动化启用顺序

1. 保持写总开关和调度器关闭，只验证账号、商品、会话、订单和供应商事实同步。
2. 配置官方 TOP 或自有授权 Gateway；验证响应字段、权限范围、事件 token 和日志脱敏。
3. 只开启一个分项策略的 `REVIEW` 模式，每日上限设为 1，人工确认一条发布/改价/下架/回复或物流动作。
4. 验证平台结果、AutoFish 本地状态、审计日志、幂等重放、超时人工接管和 Kill Switch。
5. 连续稳定后才把低风险动作切到 `AUTOMATIC`；采购/支付、退款/投诉、赔偿、法律问题和平台介入不得切换。
6. 最后启用调度器，并逐项提高限额；出现 401/403/429、风险提示或未知响应立即停止。

## 上线门禁

- `.env` 和初始管理员密码文件权限 `0600`；管理员密码至少 12 位并包含四类字符中的三类。
- 所有准备发布到闲鱼的商品必须有已启用、可追溯的供应商 SKU 链路，并通过演示来源硬门禁；演示数据不能进入发布队列、草稿、平台动作、人工回填或浏览器预填。
- PostgreSQL、Redis、worker 只在内部 Docker 网络；仅暴露前端 `18180` 与后端健康/文档端口 `18181`。
- NAS 局域网入口前建议增加受信任的 HTTPS 反向代理；未配置 TLS 时不得经公网暴露。
- `docker compose config --quiet`、Alembic 到 head、后端 Ruff/Pytest、前端 typecheck/build 全部通过。
- `/health`、`/ready`、登录、集成状态、候选导入、商品查询和备份恢复演练通过。
- 自动备份容器已写出非空 `.dump`；至少完成一次临时库 `pg_restore --list` 或恢复演练。
- 手工 `.sql.gz` 备份必须同时通过非空检查、同名 `.sha256` 校验和 `gzip -t`；脚本报错、校验失败或小于合理体积的文件不得作为恢复点。
- 真实平台准入、凭证所有权、权限范围和数据使用目的有记录；验证码/风控处理仍完全人工。
- 平台写入金丝雀、幂等重放、结果不确定、熔断、Kill Switch 与恢复演练均有审计证据。

## 日常运维

- 每日查看 `docker compose ps`、`/ready`、集成控制面和最近同步批次。
- 自动备份每 24 小时执行一次，默认保留 14 天；大升级前仍执行 `scripts/backup.sh` 手工备份。
- Adapter 反复出现 401/403/429、未知结构或超时后保持关闭，先在 Gateway/官方页面排查。
- 改管理员密码会递增会话版本，所有旧 JWT 立即失效；其他设备需要重新登录。
- 日志与快照只保存脱敏事实；不得把 `.env`、Token、Cookie 或完整买家隐私发到工单/聊天。

## 故障与回滚

1. 点击“停止所有自动化”，并设置 `AUTOFISH_ADAPTERS_ENABLED=false`。
2. 记录 correlation ID、容器版本、Alembic revision 和错误时间，不修改原始快照。
3. 回滚应用镜像前先备份数据库；数据库迁移原则上向前修复。需要恢复时按 NAS 部署文档在隔离窗口操作。
4. 验证 `/ready`、登录和数据行数，再恢复只读 Adapter。

## 仍需用户提供的上线材料

- 1688 至少 20 个真实商品的 SKU、实时价、库存、运费与业务验收结果；可通过授权结构化接口或人工核验入口补齐。若需要自动采购，还需官方交易/订单权限与支付人工确认方案。
- 闲鱼开放平台邀请准入、AppKey/AppSecret/Session 与获批业务权限，或用户自建授权 JSON Gateway URL + Token；通用私信若无官方能力，不得以 Cookie/私有协议代替。
- Gateway 的脱敏字段样本、写入幂等契约、规范化 webhook 事件样本和能力矩阵。
- 若要公网访问：域名、HTTPS 证书/反向代理方案和访问控制要求。

缺少这些材料不会影响 NAS 上的 1688 只读运行、闲鱼人工商品快照、保护模式与人工导入，但会阻止真实闲鱼同步/写入和 1688 交易闭环；这属于外部授权与业务准入门禁，不应通过技术手段绕过。
