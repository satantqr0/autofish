# AutoFish 稳定化验收报告（2026-08-26）

## 1. 验收结论

AutoFish 已达到“可在 NAS 上持续运行并进入受控灰度”的稳定化基线，本轮验收为**有条件通过**。

- 本地自动化测试、静态检查、依赖安全检查和生产构建均通过。
- NAS 上 7 个服务全部健康，数据库与 Redis 就绪，迁移处于唯一 head。
- 20 个核心 Web 页面完成已登录、只读逐页验收，全部具有有效主内容，无崩溃页，也未发现来自 AutoFish 页面域名的控制台错误。
- 发布、自动发布与 AI 客服发送已经拆成三个独立门禁，不再因开启客服而误放行发布。
- 本轮没有执行发布、回复、改价、下架、采购、退款或发货等闲鱼/1688 写操作。

这里的“有条件”是指：系统自身已经稳定，但浏览器自动化仍受闲鱼登录态、验证码、页面结构和平台规则约束；在没有企业 API 权限的情况下，不应把平台写入宣称为无人工、无风险的确定性能力。

## 2. 本轮关键修复

### 2.1 写操作与任务安全

- 修复 ClawHub 历史动作预览被新目标复用的问题，增加动作、目标、所有者和指纹绑定，阻止跨用户或过期预览执行。
- 浏览器回复成功证据与会话、消息指纹精确绑定，避免把其他会话的页面变化误判成成功回复。
- 任务领取改为原子抢占，增加租约、心跳和超时处理。
- 进入外部提交阶段后，如果结果不明确，任务直接转人工，禁止盲目重试导致重复发布或重复回复。
- 发布硬开关与 AI 客服硬开关完全分离：
  - `publish_submission_enabled` 只代表人工确认后的浏览器发布通道。
  - `customer_service_submission_enabled` 只代表浏览器客服发送通道。
  - `external_submission` 仅保留兼容用途，不再被前端用于推断发布权限。

### 2.2 AI 客服

- 增加默认关闭的浏览器 AI 客服闭环。
- 只有硬开关、全局策略和客服策略同时放行，且会话身份、最新消息和消息指纹均通过校验时，才允许自动回复。
- 高风险、身份不明、信息不足或结果不确定的会话一律转人工。
- 数字、价格、库存、物流与承诺类回复增加事实约束，避免模型编造。

### 2.3 前端可靠性

- 商品中心改为真实服务端分页，并验证第一页 20 条、第二页 16 条、前后翻页状态正确。
- 关键设置页增加脏状态保护，未修改时保存按钮禁用。
- 普通请求增加 30 秒超时，模型生成和供应商测试采用独立的较长超时。
- 商业证据录入不再用空值覆盖已有月度数据。
- ClawHub 历史动作仅展示审计信息，没有当前预览时不提供执行入口。
- 系统设置明确显示人工发布、自动发布和客服发送三个独立状态。

### 2.4 运行与供应链

- Python 生产/开发依赖改为哈希锁定，补齐 Linux `greenlet`，升级到 `cryptography 50.0.0`。
- 生产后端镜像以 UID 10001 运行，运行镜像中已移除 pip。
- 数据库连接池、连接超时、语句超时和事务空闲超时均设置边界。
- 生产环境缺少关键密钥或仍使用演示管理员配置时启动失败。
- 生产环境关闭 `/docs` 和 `/openapi.json`。
- 日志增加凭据、Cookie、Token、手机号、地址等敏感字段遮蔽。
- 管理员修改密码后递增会话版本，使其他设备的旧 JWT 立即失效。
- Compose 增加资源限制、日志轮转与健康检查。
- 数据库备份采用校验和、原子发布和严格文件权限。

## 7. 尚未消除的产品化风险

1. **平台通道风险**：没有闲鱼企业 API 权限时，浏览器桥接仍可能受登录失效、验证码、页面改版和风控影响。必须保留人工接管、幂等证据和熔断。
2. **AI 客服真实外发尚未验收**：当前没有合格的真实买家咨询，因此不能诚实宣称已经完成真实回复闭环。上线前应至少用 1 个真实咨询做人工监督验证。
3. **灰度观察不足**：建议连续运行 14 天，记录成功率、转人工率、重复写入数、任务租约超时数、会话误识别数和恢复时间。
4. **密钥轮换债务**：凭据加密密钥仍可回退到 JWT 密钥。直接更换会导致已加密的模型密钥无法解密，需编写迁移并执行受控轮换。
5. **传输安全**：当前管理入口使用 HTTP。正式对外或跨网访问前应增加 HTTPS、限制 SSH 来源，并关闭不需要的 Telnet 服务。
6. **镜像可重复性**：基础镜像使用版本标签而非不可变 digest；下一轮应固定 digest 并配置镜像来源审计。
7. **测试覆盖债务**：总体覆盖率约 68%，核心服务较高，但部分 API 路由仍偏薄；发布、回复、订单和备份恢复路径应继续补契约测试。
8. **灾备边界**：本机备份和恢复已验证，但仍需异机/离线备份；若 NAS 数据卷实际采用 RAID0，则单盘故障风险必须在商用前消除。

## 8. 商用灰度退出条件

满足以下条件后，可将结论从“有条件通过”提升为“商用通过”：

- 完成至少 1 次真实买家咨询的监督式 AI 回复，并验证会话、商品、订单和回复成功证据完全对应。
- 连续 14 天无重复发布、重复回复、越权执行或不可恢复的数据错误。
- 关键写任务成功率达到既定目标，所有不确定结果都能自动转人工。
- 完成 HTTPS、异机备份、密钥轮换方案与基础镜像 digest 固定。
- 对 PUBLISH 或 CUSTOMER_SERVICE 切换到 AUTOMATIC 前，分别完成独立审批与小流量回滚演练。
